# Ella Monitoring Android preview

Version **0.2.0-preview** (build 2). Native Java viewer for the existing [Pi collector 0.7.1 API](../node.js/API.md). Minimum Android 8.1 / API 27; compile/target API 37. The Pi remains the always-on collector and logger. This build does not require a collector update.

**Installing over 0.1.0:** its original development signing key is unavailable. This APK uses a new retained private preview key. Uninstall 0.1.0 before installing 0.2.0; this clears its settings. Keep your Pi address/token available and re-enter connection and display settings afterwards. Production signing is still to be settled.

## First connection

1. Install the development preview APK. It is a separate app named **Ella Monitoring Preview**, package `com.colonellp.ellamonitor.preview`; production identity/signing are still to be established.
2. Join the same Wi-Fi as the Pi. In **Settings**, enter `http://PI_HOST:8080` (replace the placeholder with the Pi's LAN address) and the private 64-character token from `PicoData/api.json`. On older Android, use a numeric address if `.local` resolution is unavailable. The Pi API must listen on its LAN interface.
3. Tap **Save & connect**. Android 17 asks for local-network access; grant it. The app opens connections through an available Wi-Fi/Ethernet network so a phone's mobile-data default route does not take over a local request.
4. Confirm independent **Pico live / SBMS live** status and compare readings with the existing dashboard. Check source signs/units before relying on directional charts.

The API token is encrypted with an Android Keystore AES-GCM key in app-private preferences. It is not placed in URLs/logs/exports, and connection settings are excluded from backup/device transfer. Clearing app data requires re-entering credentials. HTTP sends the token in plaintext on the LAN; HTTPS preserves normal certificate/hostname checks and supports a user-installed private CA. There is no trust-all certificate mode or redirect forwarding. No private endpoint, token, actual readings or inventory is included in source.

## Interface

- **Live data** uses the companion EQ app's logical landscape layout and uniform scaling. The reference is 1024×600 in fullscreen, with the EQ source's 1024×510 minimum windowed canvas. Android is asked to use sensor landscape; a rotated landscape canvas covers modes that ignore the request. Insets/cutouts remain respected. Current and temperature labels/values share one line. Flags occupy one box above the central 2×4 comparisons. Barometer, LPG/water and pitch/roll occupy the next box; battery details and available cell channels occupy the bottom strip. Relevant element gaps are 6 logical pixels.
- Bottom controls are **Preset ▾ → Live data → Charts**, then **Keep screen on → Full screen → Lock → Settings**. The last four use the EQ app's vector icon artwork and compact boxed style. **Lock** prevents monitoring readout popups/long-press edits while readings continue. **Full screen** hides system bars; swipe to reveal them. **Keep screen** remains foreground-only and retains detected FYT handling; phone behaviour uses ordinary Android screen flags. FYT interaction with the EQ app still needs head-unit testing.
- Tap an unlocked readout for its existing snapshot and recorded summaries. Those summary popups and chart contents retain their 0.1.0 appearance/behaviour because their redesign is excluded from this build. Flags/unlogged readings remain live-only. The existing Pico load sum/calculations are unchanged; no new aggregate logging or history schema is introduced.
- **Settings** is a page with Connection, Display & App, Theme & Appearance, and Labels & Export sections. **Hide app title** removes the title while preserving status/navigation. **Display local clock** leaves UTC history boundaries unchanged. **Persistent app notification** creates an ongoing return-to-app notification when backgrounded, matching EQ's persistence feature. Grant notification permission on Android 13+ to see it. This option does not add background polling, alerts or data logging on Android.
- **Settings → Theme & Appearance** provides the EQ theme engine and colour wheel/brightness/hex picker. Change live gauge colours, panels, borders, background, text and button roles; choose Sans, Condensed, Medium, Light or Monospace. Fixed green/red active-flag semantics remain readable and distinct. Save/load/update/rename/delete named themes, or restore Default. All in-scope dialogs follow the current theme; existing summary/chart surfaces are deliberately excluded.
- **Preset ▾** offers Save settings as, Update when changed, Manage presets and saved presets. Manage supports Rename, Delete and View values. A preset saves labels, theme, clock/title display and chart selection. It never saves API credentials or changes the Pico/SBMS configuration. The monitoring app has no DSP/audio factory presets. Saved themes can be reused independently of viewer presets.
- **Settings → Edit display labels** or an unlocked long-press renames elements/headings. Restore original labels in the editor. Aliases retain the existing stable bindings and do not change units, device names or database history. Current labels omit the extra current suffix by default.

## History and exports

- Open **Charts**, then use the **6h / 12h / 24h / Week / Month** header controls. These are rolling views by default; Month means **30 days** in this preview. Electrical resolutions are minute / hour / day respectively; pressure/temperature use available hour/day data. History refreshes approximately every 30 successful live polls while its screen is open, or with **Refresh**. Previous/Now/Next navigation is available.
- **Defined UTC** uses midnight-aligned 6/12-hour blocks, calendar days, Monday-based weeks and calendar months. These are explicit preview defaults for review. Optional local clock display applies the device timezone/BST rules to labels, without changing UTC buckets or reconstructing local-midnight totals.
- Quantities keep their units: mean W/A/V, last recorded SOC, and recorded Wh/Ah per period. Voltage/SOC use lines. **Bars** selects Wh/Ah, with green in/amber out only when channel polarity is verified. Load channels reverse the forward/reverse legend appropriately; battery bars describe **net** battery flow, not simultaneous gross charging and consumption. Unknown polarity shows unclassified signed net values. Temperature offers last/low/high where those statistics exist.
- Missing periods are gaps; null is not zero. Tap a recorded interval for its source, value, partial state and coverage. Rolling cutoffs select intersecting **whole UTC buckets**, explicitly labelled; no proportional energy estimate is presented as exact. Short-data retention, outages and incomplete checkpoints limit available summaries. Environmental points and SOC are recorded readings, not continuous coverage guarantees.
- **Settings → Export current chart range** or the chart's export button writes CSV through Android's file picker. Load a chart first. It exports the selected metric/range's saved statistics, source IDs/original names, edited quantity label, UTC boundaries, units, extrema, signed/directional energy, coverage and partial/edge markers. Credentials are excluded. User labels are escaped for spreadsheet safety. It does not export a database backup or nonexistent raw historical samples.

The app polls live data only in the foreground, about one second after each completed request. API failures clear current values; client monotonic ageing independently expires Pico/SBMS at the collector's default 2/3-second limits. A privately configured longer freshness threshold on the Pi does not extend the app's conservative limits. Background/closed devices continue logging on the Pi; this preview includes no alerts, offline cache or remote access.

## Build

Source is in [source/](source/). Install JDK 17 and the Android SDK platform `platforms;android-37.0` plus Build Tools 36.0.0 using Android Studio/SDK Manager. Set your local `ANDROID_HOME` or private `source/local.properties`; do not commit SDK paths. The Gradle wrapper pins 9.6.0 with its distribution checksum, and AGP is pinned to 9.4.0.

```bash
cd android/source
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

The development APK is `app/build/outputs/apk/debug/app-debug.apk`. Keep development signing material private. This preview uses development signing; it does not establish a production signing identity, publish a GitHub APK release or enable self-updates. Rebuilding elsewhere with another debug key will require uninstalling the existing preview (which clears its settings), so final signing must be settled before regular updates.

The app adds no third-party runtime dependency: HTTP/JSON, UI, storage encryption and plotting use Android/Java APIs. JUnit, a test-only JSON implementation and Robolectric are test dependencies. The standard Gradle wrapper retains its generated Apache 2.0 notices. Appearance, scaling, vector controls, the colour wheel and FYT screen behaviour are adapted from the owner's [EQ app reference](APP-PLAN.md#source-references-for-reuse); no audio/DSP operations or vendor implementation/assets are copied. No SignalK/Pico protocol port is distributed inside this APK.

See [CHANGELOG.md](CHANGELOG.md), [BUILD-VALIDATION.md](BUILD-VALIDATION.md) and [NEXT-BUILD-CHANGES.md](NEXT-BUILD-CHANGES.md). The owner reports Pico/SBMS API connectivity with the first preview. This new layout/persistence build still needs actual phone/head-unit checks, including certificate trust, Android 17 permission prompts, recovery, screen handling, portrait rotation and visual fit. GitHub update download/install, production signing/releases, background alerts, cloud relay, direct Pico/MQTT mode and Simarine settings are subsequent stages.
