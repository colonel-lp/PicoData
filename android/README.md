# Ella Monitoring Android preview

Version **0.22** (build 4). Native Java viewer for the existing [Pi collector 0.7.1 API](../node.js/API.md). Minimum Android 8.1 / API 27; compile/target API 37. The Pi remains the always-on collector and logger. This build does not require a collector update.

**Owner-built update:** compile `Ella-monitoring-v0.22.apk` in Android Studio and use the same signing key as the installed app to update in place and preserve settings. The package is unchanged. The earlier 0.1.0 key is different and still requires reinstalling. This remains the existing development package; a separate production identity is not introduced.

## First connection

1. Install the development preview APK. It is a separate app named **Ella Monitoring**, package `com.colonellp.ellamonitor.preview`; production identity/signing are still to be established.
2. Join the same Wi-Fi as the Pi. In **Settings**, enter `http://PI_HOST:8080` (replace the placeholder with the Pi's LAN address) and the private 64-character token from `PicoData/api.json`. On older Android, use a numeric address if `.local` resolution is unavailable. The Pi API must listen on its LAN interface.
3. Tap **Save & connect**. Android 17 asks for local-network access; grant it. The app opens connections through an available Wi-Fi/Ethernet network so a phone's mobile-data default route does not take over a local request.
4. Confirm independent **Pico live / SBMS live** status and compare readings with the existing dashboard. Check source signs/units before relying on directional charts.

The API token is encrypted with an Android Keystore AES-GCM key in app-private preferences. It is not placed in URLs/logs/exports, and connection settings are excluded from backup/device transfer. Clearing app data requires re-entering credentials. HTTP sends the token in plaintext on the LAN; HTTPS preserves normal certificate/hostname checks and supports a user-installed private CA. There is no trust-all certificate mode or redirect forwarding. No private endpoint, token, actual readings or inventory is included in source.

## Interface

- **Live data** uses the companion EQ app's logical landscape layout and uniform scaling. Controls use a 1024px-wide logical landscape canvas with width-based uniform scaling; available height changes with system bars, so bottom controls keep the same height. Android is asked to use sensor landscape; a rotated landscape canvas covers modes that ignore the request. Insets/cutouts remain respected. Current and temperature labels/values share one line. The Ella Monitoring title sits above the flags, which occupy one box above the central 2×4 comparisons. All gauges have padded bounding boxes. Currents:, Temps: and Ella Monitoring use the Title background/outline theme roles. Barometer, LPG/water and pitch/roll occupy the next box; battery details and available cell channels occupy separate boxes in the bottom strip. Each element is a themed button. Current rows are evenly spaced with 6px gaps, without blank rows. Pitch/roll use -5 to +5, a needle and colour only from zero to its position. V[P]/V[S] use raw Pico battery/starter voltage, independently of logged voltage references. Runtime follows the verified Node-RED chain with Pico nominal/remaining capacity and raw battery current, without a seven-day fallback. Relevant element gaps are 6 logical pixels. Lower voltage/Ah/runtime values are centred, with larger Ah/runtime text; cell-voltage and delta text have 20px side padding. Unavailable readings show —. Each gauge popup offers Highlight background, using its separate theme colour; normal central/environmental panels use Gauge panel 1/2 and their respective outline colours.
- Bottom controls show **PRESET • loaded name** and **THEME • loaded name**, matching the EQ app. Modified settings show **UNSAVED** and the modification dot; saving/restoring clears them. Controls remain available on Settings too, including **Theme** beside **Preset**. The update-frequency choices open above the **Updates:** button.
- Bottom controls are **Preset ▾ → Theme ▾ → Live data → Charts**, then **Keep screen on → Full screen → Lock → Settings**. The last four use the EQ app's vector icon artwork and compact boxed style. **Lock** prevents monitoring readout popups/long-press edits while readings continue. **Full screen** hides system bars and expands the usable canvas; swipe to reveal them. **Keep screen** remains foreground-only and retains detected FYT handling; phone behaviour uses ordinary Android screen flags. FYT interaction with the EQ app still needs head-unit testing.
- Tap an unlocked readout for its existing snapshot and recorded summaries. All popups follow the current theme and EQ dialog styling; summary content and chart calculations remain unchanged. Flags/unlogged readings remain live-only. The existing Pico load sum/calculations are unchanged; no new aggregate logging or history schema is introduced.
- **Settings** is a page with Connection, Display & App, Export and an untitled bottom-right control block. The app-wide title remains removed; the dashboard retains its Ella Monitoring header. **Hide connection status** hides the status line on monitoring pages; Settings always hides it. The lower-right block contains two rows: Updates: and a reserved button position, then Changelog / Update and Back; the version sits below. **Display local clock** leaves UTC history boundaries unchanged. **Persistent app notification** creates an ongoing return-to-app notification when backgrounded, with one line saying Ella Monitoring. Grant notification permission on Android 13+ to see it. This option does not add background polling, alerts or data logging on Android.
- **Main-page Theme ▾ → Edit theme** provides the EQ theme engine and colour wheel/brightness/hex picker. Change live gauge colours, panels, borders, background, text and button roles; choose Sans, Condensed, Medium, Light or Monospace. Fixed green/red active-flag semantics remain readable and distinct. Save/load/update/rename/delete named themes, or restore System default. Every popup follows the current theme. OK and Cancel return to the colour-editor list without added dimming; Cancel/outside dismissal restores the original colour. Named themes are JSON files in **Downloads/ella-monitoring/themes**; old saved preferences migrate once each file is written. Android 8.1/9 requests storage permission; Android 10+ uses owned Downloads files.
- **Preset ▾** offers Save settings as, Update when changed, Manage presets and saved presets. Manage supports Rename, Delete and View values/Copy. System default restores the default viewer settings. A preset saves labels, theme, gauge highlighting, clock/connection-status display, chart selection, keep-screen/fullscreen/lock/persistence settings and update-check frequency. The dot indicates differences from the selected saved preset; the Theme dot compares colours/font with the saved theme. It never saves API credentials or changes the Pico/SBMS configuration. The monitoring app has no DSP/audio factory presets. Saved themes can be reused independently of viewer presets.
- **Theme ▾ → Edit display labels** or an unlocked long-press renames elements/headings. Restore original labels in the editor. Aliases retain the existing stable bindings and do not change units, device names or database history. Current labels omit the extra current suffix by default. The compact rename popup contains the editable label and Cancel/Restore/Save buttons, with no header/explanation.

## History and exports

- Open **Charts**, then use the **6h / 12h / 24h / Week / Month** header controls. These are rolling views by default; Month means **30 days** in this preview. Electrical resolutions are minute / hour / day respectively; pressure/temperature use available hour/day data. History refreshes approximately every 30 successful live polls while its screen is open, or with **Refresh**. Previous/Now/Next navigation is available.
- **Defined UTC** uses midnight-aligned 6/12-hour blocks, calendar days, Monday-based weeks and calendar months. These are explicit preview defaults for review. Optional local clock display applies the device timezone/BST rules to labels, without changing UTC buckets or reconstructing local-midnight totals.
- Quantities keep their units: mean W/A/V, last recorded SOC, and recorded Wh/Ah per period. Voltage/SOC use lines. **Bars** selects Wh/Ah, with green in/amber out only when channel polarity is verified. Load channels reverse the forward/reverse legend appropriately; battery bars describe **net** battery flow, not simultaneous gross charging and consumption. Unknown polarity shows unclassified signed net values. Temperature offers last/low/high where those statistics exist.
- Missing periods are gaps; null is not zero. Tap a recorded interval for its source, value, partial state and coverage. Rolling cutoffs select intersecting **whole UTC buckets**, explicitly labelled; no proportional energy estimate is presented as exact. Short-data retention, outages and incomplete checkpoints limit available summaries. Environmental points and SOC are recorded readings, not continuous coverage guarantees.
- **Settings → Export current chart range** or the chart's export button writes CSV through Android's file picker. Load a chart first. It exports the selected metric/range's saved statistics, source IDs/original names, edited quantity label, UTC boundaries, units, extrema, signed/directional energy, coverage and partial/edge markers. Credentials are excluded. User labels are escaped for spreadsheet safety. It does not export a database backup or nonexistent raw historical samples.

The app polls live data only in the foreground, about one second after each completed request. API failures clear current values; client monotonic ageing independently expires Pico/SBMS at the collector's default 2/3-second limits. A privately configured longer freshness threshold on the Pi does not extend the app's conservative limits. Background/closed devices continue logging on the Pi; this preview includes no alerts, offline cache or remote access.

## Updates

**Settings → System → Changelog / Update** displays the complete maintained changelog (also bundled for offline use) and checks PicoData releases manually. When a newer compatible asset exists, **Download & Install** verifies size/checksum, package, newer Android versionCode and signing certificate, then opens Android's installer. Allow this app to install unknown apps if prompted. Android controls the final installation. A cancelled installer retains the download for retry; cleanup occurs after the installed version confirms success.

Automatic checking uses the saved **Off / 1hr / 3hr / 6hr / 12hr / 24hr** interval while the app is foregrounded. Default is 24hr. Off disables automatic checks, including startup; manual checks remain available. Nothing polls for updates while the app is backgrounded. Release publication is separate from committing source, and the feed reports no APK release when none is attached. Release notes should include the Android versionCode and complete changelog; assets retain the same signing key/package.

## Build

Source is in [source/](source/). Install JDK 17 and the Android SDK platform `platforms;android-37.0` plus Build Tools 36.0.0 using Android Studio/SDK Manager. Set your local `ANDROID_HOME` or private `source/local.properties`; do not commit SDK paths. The Gradle wrapper pins 9.6.0 with its distribution checksum, and AGP is pinned to 9.4.0.

```bash
cd android/source
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

Android Studio/Gradle produces `app/build/outputs/apk/debug/Ella-monitoring-v0.22.apk` (and the same filename in the release output directory). This source-only delivery does not include an assembled APK. Keep development signing material private. Use the same private signing key as your installed version, and verify package/version/certificate when compiling an update. The app uses the PicoData GitHub release feed; APK assets must be named Ella-monitoring-vX.XX.apk. A source commit alone does not create an APK release. Rebuilding elsewhere with another debug key will require uninstalling the existing preview (which clears its settings), so the retained key must be preserved for future updates.

The app adds no third-party runtime dependency: HTTP/JSON, UI, storage encryption and plotting use Android/Java APIs. JUnit, a test-only JSON implementation and Robolectric are test dependencies. The standard Gradle wrapper retains its generated Apache 2.0 notices. Appearance, scaling, vector controls, the colour wheel and FYT screen behaviour are adapted from the owner's [EQ app reference](APP-PLAN.md#source-references-for-reuse); no audio/DSP operations or vendor implementation/assets are copied. No SignalK/Pico protocol port is distributed inside this APK.
